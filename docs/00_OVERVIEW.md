# 00 · Overview — PRAXIS / RegPilot

> **SEBI TechSprint 2026 · Problem Statement 2 — Agentic Compliance**

**PRAXIS** (short for *Praxis — from obligation to evidence*, also shipped as **RegPilot**) is an
agentic compliance platform that reads SEBI circulars, extracts the regulatory obligations they
impose, translates them into machine-evaluable rules, assignable workflow tasks, and evidence
requirements, and tracks execution end-to-end — with a human-in-the-loop review gate before
anything becomes "live."

This documentation set is the submission guide. It maps every capability to the problem
statement, shows how the system is built, how it is run, how it is demonstrated, and how it
would be judged.

---

## The problem in one paragraph

SEBI issues hundreds of pages of circulars. Buried in them are discrete compliance duties —
*"formulate and annually review a board-approved cyber security policy," "report material
disclosures by T+1," "appoint a compliance officer for investment advisers."* Firms currently
parse these by hand, maintain spreadsheets, and risk missing obligations or misreading
timelines. PS2 asks for an **agentic** system that can ingest a circular, identify and classify
obligations, and drive them through to evidence of compliance.

## The solution in one paragraph

PRAXIS ingests a circular PDF and runs a **scale-aware processing funnel** that reserves the
LLM for only the ~10–20% of content that genuinely needs it (a 414-page / 870-section master
circular costs ~18 LLM calls instead of 800+). Extracted obligations land in a review queue;
an officer approves, edits, or rejects each one. On approval, Phase B generates rules, tasks
with owners and deadlines, and evidence collectors. A **knowledge graph** projection shows how
regulations, obligations, departments, owners, and evidence connect — including cross-document
supersession. The whole journey — every extraction, approval, edit, and assignment — is
recorded in an append-only audit log, and the model runs locally, so no regulatory content
leaves the client boundary.

## Quick facts

- **Stack:** FastAPI (Python) · React + TypeScript + Vite · SQLAlchemy 2.x · LangGraph ·
  local LLM via **Ollama** (default `qwen2.5:7b`).
- **Storage:** relational store is the single source of truth (SQLite for dev, Postgres in
  Docker). The knowledge graph is a projection over it, so it can never drift from the audit
  trail.
- **Scale:** funnel reduces LLM calls by ~85–90% vs. naive section-by-section extraction.
- **Governance:** nothing generated by the pipeline becomes authoritative without a human
  approval; every mutation is audit-logged.
- **Repos/remotes:** `origin` `github.com/InferiaAI/praxis`, `hooman` `github.com/HoomanBuilds/praxis`.
